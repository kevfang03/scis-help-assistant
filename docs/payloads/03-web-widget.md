# Execution Payload 03: local web app, embeddable chat widget, feedback, caps

**Suggested effort level:** high.

**Depends on:** payload 02's interfaces (`Engine`, `Conversation`, `Answer`, `SourceLink`, `feedback.record`, `AnswerSettings`). It can start before 02 is finished by coding against those interfaces with a fake engine; the end-to-end check needs 02 done.

## Goal
`uv run scis-help web` starts a local site with:
- `/`: a neutral demo host page with the chat-bubble widget (public mode);
- `/desk`: the same widget in desk mode;
- `widget.js`: one script tag embeds the widget on any page.

The widget lets users ask, see short answers with numbered source links, answer one clarifying question, and rate answers 👍/👎. The server enforces message, session and rate caps.

## Interfaces

```python
# common/config.py
class WebSettings(BaseModel):
    host: str = "127.0.0.1"
    port: int = 8765
    allowed_origins: list[str] = []          # CORS for embedding on another local page; empty = off
    rate_per_minute: int = Field(default=10, ge=1)      # per client IP
    session_max_messages: int = Field(default=20, ge=1)
    session_max_tokens: int = Field(default=40_000, ge=1_000)
    session_idle_minutes: int = Field(default=60, ge=5)
    max_sessions: int = Field(default=500, ge=10)       # oldest idle sessions evicted beyond this
    desk_local_only: bool = True                         # /desk and mode=desk only from 127.0.0.1/::1
```

HTTP API (JSON):
```text
POST /api/chat
  request:  {"session_id": "<uuid4 from the widget>", "message": "...", "mode": "public" | "desk"}
  200:      {"answer_id", "status", "answer_html", "sources": [{"n", "url", "title", "heading", "used"}],
             "clarifying_question", "scrub_notice", "notice"}      # notice: a short cap/limit message or null
  400 bad input · 403 desk from non-local · 429 rate limit (with Retry-After)
POST /api/feedback
  request:  {"session_id", "answer_id", "helpful": true | false}
  204;      404 if the answer_id isn't in that session (only answers from the same session can be rated, once)
GET  /api/health → {"ok": true, "index_pages": n, "llm": "ready" | "no_key" | "disabled"}
GET  /  /desk  /widget.js  /widget.css
```
`session_id` is opaque, generated by the widget (`crypto.randomUUID()`), kept in `sessionStorage`. The server keeps `Conversation` plus the session's recent `Answer`s (last 20) in memory, keyed by it. Unknown ids create a new session. **Never log or store session ids, IPs or user agents** (the rate limiter holds IPs in memory only).

## Behaviour
1. **Caps, before calling the engine:** rate limit per IP (sliding 60 s window) → 429 with a friendly `Retry-After`. Session over `session_max_messages` or `session_max_tokens` → 200 with `status: "not_covered"`-style text "This chat has reached its limit. Please start a new chat or talk to a person at {help_contact}." and `notice` set; no engine call. Message empty or over `answer.max_message_chars` → 400.
2. **Engine:** `Engine` built once at startup (index loaded once). `engine.ask` runs in a threadpool (`run_in_threadpool` or a sync endpoint) so the event loop isn't blocked.
3. **Rendering (`render.py`):** `answer.text` markdown → HTML with `markdown-it-py` in a safe configuration: `html=False`, links allowed only when the href is one of the answer's source URLs (otherwise render the link text only), allowed elements p, ul, ol, li, strong, em, code, pre, a, br. `[n]` references become superscript links to the matching source. Unit-test that `<script>`, `onerror=`, `javascript:` links and model-written external links never survive.
4. **Desk mode:** with `desk_local_only`, `/desk` and `mode=desk` from a non-loopback client → 403.
5. **Feedback:** `feedback.record(answer, helpful)` once per answer id.
6. **Startup:** `scis-help web` checks the index (exit 4 with the crawl/index hint if missing), warns (doesn't fail) if no key is saved (answers will be `links_only`), prints `Open http://127.0.0.1:8765/ (Ctrl+C to stop)` and opens the browser unless `--no-browser`. Binding to anything other than loopback prints a warning that the app has no authentication.

## Widget (`widget.js` + `widget.css`)
- Plain JavaScript, no framework, no build step, no external requests (no CDNs, fonts or analytics). One `<script src=".../widget.js" data-mode="public" defer></script>`; it derives the API base URL from its own `src`, so it works when embedded on another local page (with `allowed_origins`).
- Rendered in a **Shadow DOM** attached to a host `div`, with `widget.css` loaded into the shadow root.
- A round bubble bottom-right ("?" or a chat icon drawn in CSS/inline SVG) opens a panel (about 360×520 px; full-screen under 480 px wide). Header: "Help Assistant (unofficial)". Under it, always visible: "Don't enter passwords or student IDs." Footer: "Unofficial student project · answers come from public SCIS support pages".
- Messages: user bubbles via `textContent`; assistant answers via the server's sanitised `answer_html`; sources as a numbered list of links (`target="_blank" rel="noopener noreferrer"`); desk mode adds a collapsed "Also retrieved" list. `scrub_notice` → a small notice line. Clarifying question shown as a normal assistant message; the next user message is the reply.
- 👍/👎 under each `answered` answer; after a click both are disabled and "Thanks!" appears.
- A "New chat" button makes a new `session_id`.
- Accessibility: the bubble and buttons are `<button>`s with `aria-label`s; the panel is `role="dialog"` with a label; Enter sends, Shift+Enter makes a newline, Esc closes; focus moves into the panel on open and back to the bubble on close; a polite live region announces new answers; contrast ≥ 4.5:1.
- A "Thinking…" indicator while waiting; the input is disabled during a request; errors (network, 429) show a short message in the chat.
- **Neutral styling:** system font stack, grey/blue neutral palette, no Drexel/SCIS logos, colours (no Drexel navy-and-gold), mascots or official wording.
